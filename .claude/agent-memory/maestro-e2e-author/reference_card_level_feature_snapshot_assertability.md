Flow proving this: `set-selector/card-autopopulates-features.yaml` (GREEN locally, single attempt, ~162s). Card-level companion to [[reference_write_once_feature_snapshots_neo71_74]] (which asserts the same defaults only at the SET panel) and [[reference_playerids_only_real_cards_and_drawer_scroll]] (drawer swipe technique).

**The card-level feature: both card-creation paths seed `cardChecklist.features` byte-identically** — `addCustomCard` = `{...parentNode.features, ...deriveCardObservedFeatures(...)}` and `commitCardChecklist`'s marketplace INSERT branch = `{...inheritedFeaturesOrUndefined, ...deriveCardObservedFeatures(card)}`, where `inheritedFeaturesOrUndefined === leafNode.features === parentNode.features`. So a per-worker CUSTOM CARD under a FRESH custom leaf is the faithful, collision-free, locally-green proxy for a "freshly-synced" card's inherited defaults. A genuinely marketplace-synced card CANNOT prove this locally: (a) a custom subtree short-circuits the BSC/SL adapters (isCustomSubtree, NEO-22) → never gets synced cards; (b) real shared sets (2024 Topps Chrome Base) were synced on shared dev BEFORE these defaults existed → their leaf snapshots predate them (write-once, never recomputed) → their synced cards render the fields blank locally; and editing a real shared set concurrently violates data-isolation. In CI's fresh preview the real synced cards DO carry them, but that path isn't locally assertable.

**"Edit card N" opens the CardDetailPanel DRAWER, not an inline form.** The drawer header reads "Card #N  CUSTOM" with up/down/× controls; its body embeds the CardFeaturesEditor (the "Show features editor"/"Card features editor"/"Hide features editor" toggle + "Cancel card edit" footer button that card-features-editor-toggle and card-detail-panel also drive — all the same drawer). Do NOT use `scrollUntilVisible` to reach a feature row below the drawer fold: the drawer is right-anchored (~480px, x≈544-1024) and scrollUntilVisible swipes from viewport-centre x≈512 → lands on the BACKDROP → never scrolls the drawer's inner container → `ElementNotFound`. Use MANUAL in-drawer swipes `- swipe: {start: "80%, 80%", end: "80%, 40%"}` (x=80% is inside the drawer), then a plain `assertVisible` of the combined `{id:"Value for <Label>", text:<value>}`. Two ~250px swipes walk the whole physical block into view.

**Which card-feature VALUES render (verified via CI screenshot at the expanded drawer, custom sport = no League row):** near-top (no swipe): Era(select), Vintage(derived span), **Season**(text input = the year value, e.g. "2026"), Manufacturer(text), Card Type(text "Insert"/"Base"), **Variation**(text "Base" — key parallelName, LABEL RENAMED "Parallel/Variety"→"Variation" NEO-71-74 so aria = "Value for Variation"), Short Print(select), **Reprint (CHECKBOX — value UNREADABLE, don't assert)**, Signed By(text), Rookie/Prospect(checkbox). Below the fold (need swipes): Memorabilia Relic(checkbox), **Country of Origin**="USA", **Card Size**="Standard", **Material**="Card Stock" (label is "Material", key cardMaterial), **Card Thickness**="20pt", **Language**="English", Event/Tournament, Convention/Event, UPC. **AUTOGRAPHED IS NOT IN THIS EDITOR** — CardFeaturesEditor.tsx filters `key==="autographed"`; it's promoted to an ALWAYS-VISIBLE grid cell in the CardDetailPanel body at pos 7 (next to Print run), BELOW the whole expanded editor+title+desc+attributes. So `Value for Autographed` is UNREACHABLE from inside the expanded editor (this broke card-autopopulates + signed-by in CI run 29554529758). The card flow now asserts Season (no swipe) then Country of Origin/Card Size/Material/Card Thickness/Language (swiped) — Autographed default "None" coverage moved to card-autograph-always-visible-saves (collapsed editor + 1 swipe reaches pos 7). isReprint remains the documented skip.

**Fresh-leaf discipline:** the set basename must be NEW to the suite so its FIRST creation carries the current derivation (write-once; /testing/reset never wipes the GLOBAL selectorOptions catalog). The flow uses `cap-${WORKER_INDEX}` (introduced by it, never existed before) via util-add-custom-card → util-drill-to-custom-set (fixes E2E Test Sport <w>/2026/Topps; only SET_NAME varies). The persistent "2026" year node DOES carry season (asserted GREEN). If a NEW setName-level default is added and asserted here, BUMP the basename (cap→cap2) so the set is recreated fresh — same generation-bump rule as new-chain.

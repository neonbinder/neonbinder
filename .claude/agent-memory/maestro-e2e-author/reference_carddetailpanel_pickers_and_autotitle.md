CardDetailPanel (`components/SetSelector/`) redesign covered by these flows (all GREEN locally, per-worker custom subtree under `E2E Test Sport N/2026/Topps`, drill via `util-add-custom-card`): `player-picker-create-custom-card.yaml`, `team-picker-create-custom-card.yaml`, `card-autograph-always-visible-saves.yaml`, `custom-card-row-opens-panel-with-autotitle.yaml`.

**Drawer body order (collapsed features editor):** 1 Card name · 2 Teams (TeamPicker) · 3 "Show features editor" (collapsed) · 4 Card title · 5 Card description · 6 Attributes chips · 7 grid[Print run | Autographed select] · 8 Variation · 9 Players (PlayerPicker) · 10 Inherited from set · 11 Images. So **Teams is near the TOP (no scroll)**; **Players is near the BOTTOM** — reach it with ~3 manual in-drawer swipes `start:"80%,80%" end:"80%,20%"` (x=80% is inside the right-anchored ~480px drawer; a viewport-centre scroll lands on the backdrop). Scrolling to the bottom parks "Add player" in the upper-middle (Inherited+Images sit below it) leaving room for the popover which opens BELOW the trigger.

**PlayerPicker/TeamPicker aria-labels (identical shape):** container `Player picker`/`Team picker`; trigger `Add player`/`Add team` (renders "+ Add player"); popover input `Search players`/`Search teams`; a match row `Add <name>`; **create row `Create player <name>`/`Create team <name>`** (renders `+ Create "<name>"`, appears only when the typed query has NO exact match — use a UNIQUE name like `NBPlayer${output.ATTEMPT_TOKEN}` to guarantee it — separator-free, NEO-260); chip remove button `Remove player <name>`/`Remove team <name>` (proves the chip). `findOrCreate` creates the ENTITY, but **playerIds/teamOnCardIds are part of the drawer's dirty draft → you MUST tap `Save card edit` to attach to the card** (unlike per-row features which persist immediately). Save button is in the sticky footer (outside the scroll body/open popover) — tap it directly; do NOT press Escape to close the popover first (Escape bubbles to the panel's document keydown → `onClose()` discards the unsaved draft). The create-new path is THE gap being closed: it lets a CUSTOM card hold players/teams at all (sync never populated them).

**No seeded team fixture exists any more (NEO-214).** The "Seed Test Teams" button, the `teams.seedTestTeams` mutation and the Yankees/Mets/"E2E Fixture Player" rows are all gone, and the scripted reset leaves `teams`/`players` EMPTY at the start of every run. Every flow that needs a team creates its own through TeamPicker's `+ Create` row (`id: "Create team <name>"` → `teams.findOrCreate`), named per-worker AND per-attempt — per-attempt is mechanical, not paranoia: the create row is offered only while no team of that name exists, so a leftover row renders `Add <name>` instead. Prefixes are registered in `.maestro/SET-REGISTRY.md` → "Team names". `/admin/teams` has NO create control by design, so a flow needing a team's COLOURS creates it in a picker (the /admin/players career editor is the one outside the cascade) and then colours it on /admin/teams. `teams.list(sport, limit)` = first `limit` by index/creation order.

**Autographed dropdown** (NEO-71-74): unified into ONE always-visible `<select>` at drawer position 7 (next to Print run), promoted OUT of the features editor (CardFeaturesEditor.tsx FILTERS `key==="autographed"` → NOT rendered inside it); aria-label `Value for Autographed`, options None/On Card/Sticker/Label; **saves immediately via setCardFeature (NOT part of Save/dirty)** — proven by change→Cancel→reopen→still set. It sits BELOW the whole editor+title+desc+attributes, so it is UNREACHABLE with a small swipe while the editor is EXPANDED — reach it only with the editor COLLAPSED (pos 7 then just past the fold): ONE in-drawer swipe `start:"80%,70%" end:"80%,35%"` lifts it. To prove "not behind Show features", assert `Show features editor` still present (collapsed) then find `Value for Autographed`. Native `<select>` type-ahead: `tapOn id` + `inputText "O"` → selects "On Card" → onChange; `<select>` getNodeText = selected option, so `{id:"Value for Autographed", text:"On Card"}` asserts selection.

**Testing BOTH Autographed (pos 7) AND Signed By (still a row INSIDE the editor) in one flow** (signed-by-autofills): they can NEVER be on-screen together and page-centre scroll can't drive the drawer. Drive layout DETERMINISTICALLY via the editor's own Show/Hide toggle (a button tap): EXPAND + `swipe 80%,60%→80%,38%` reaches Signed By; a big reset `swipe 80%,25%→80%,90%` (clamps at scrollTop 0) returns to the toggle; COLLAPSE (tap `Hide features editor`) then `swipe 80%,70%→80%,35%` reaches Autographed at pos 7. Blind long swipes across the expanded editor were what CI-broke the old flow.

**Auto-generated listing title/description now PRE-FILLS Card title/Card description at card creation** (NEO-24, generateListingTitle/Description in addCustomCard — write-once). A maestro-web `tapOn` on a PRE-FILLED input drops the caret roughly at the clicked character (MID-string), so `inputText` INSERTS your text contiguously into the middle — you CANNOT cleanly full-clear it (eraseText from a mid-caret leaves the right portion). To assert an edit persisted, type a unique marker and assert it as a **regex-contains substring** `{id:"Card title", text:".*<marker>.*"}` (input getNodeText = full value, unaffected by CSS truncation) — NOT an exact match. This broke card-detail-panel in CI (its exact-title assert assumed an empty field).

**Whole-row click opens the panel** (CardChecklistItem, NEO): the row's own `onClick` fires `onEdit`; tap the card-number cell `text:"#<cardNumber>"` (NOT the name, NOT Edit/Del which stopPropagation) to open. Assert the header `.*Card #<num>.*` + `Card name` input.

**Auto-generated listing title** (`generateListingTitle`, addCustomCard + commitCardChecklist, write-once): a new card's `Card title` input is non-empty and ALWAYS ends with ` #<cardNumber>` (card number is the one token never truncated; ~80-char eBay cap). Assert via `{id:"Card title", text:".*#<cardNumber>.*"}` (input getNodeText = its value). Old behavior left it blank → would fail. `Card description` similarly auto-filled.

**Checkbox→toggle-pill (NEO-71-74, FeatureValueControl):** `isReprint`/`isRelic`/`isProspect` render as `<button aria-pressed>` (was `<input type=checkbox>`), but the `Value for <label>` aria-label is PRESERVED — so `tapOn id:"Value for Reprint"` still works (e.g. topps-chrome-add-feature taps it + asserts "Saved Reprint" toast). No existing flow read a checkbox `checked:`/`state:` selector, so nothing broke. Toggle state is still not Maestro-readable (aria-pressed not in hierarchy) — assert the SAVE side effect (toast / persisted value), not the pill state.

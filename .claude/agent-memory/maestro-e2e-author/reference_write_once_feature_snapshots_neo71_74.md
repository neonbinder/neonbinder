Flow proving this: `set-selector/new-chain-autopopulates-features.yaml` (GREEN locally, single-attempt). Companion to [[reference_typed_feature_controls_neo71_74]].

**The feature (write-once feature snapshots):** every selectorOptions node gets a COMPLETE `features` snapshot computed ONCE at creation (`convex/selectorOptions.ts` addCustomSelectorOption/storeSelectorOptions: `{...parent.features, ...deriveOwnLevelFeatures(level,value)}`). `SetAttributesPanel` reads `row.features[key]` DIRECTLY — no live inheritance. Derivation lives per-level in `deriveOwnLevelFeatures` (`convex/features/deriveCardFeatures.ts`): sport→league (4 real sports only), year→era+vintage (4-digit year; ≤1979 ⇒ non-Modern era, vintage="true"), manufacturer→manufacturer (verbatim), variantType/insert/parallel→cardType (Base/Insert/Parallel), setName→isReprint="false" + autographed="None" (autographed default added 2026-07-15, same mechanism as isReprint: `deriveSetLevelFeatures` returns it unconditionally, `LEVEL_HEURISTIC_KEYS.setName` lists it → originates at setName, cascades down). variantType(Base) also→parallelName="Base".

**Which panel feature VALUES are Maestro-assertable — CORRECTED 2026-07-12 (was WRONG before):** ALL of them, including `<input>` and `<select>`. Proven empirically (new-chain + sport-level-league flows GREEN) AND by reading `~/.maestro/lib/maestro-client.jar!maestro-web.js` `getNodeText` (cli 2.6.0):
- `<input>` node text = `value || placeholder || ariaLabel` → the input's CURRENT VALUE **is** matchable (Reprint "false", Card Type "Base", Parallel/Variety "Base", Manufacturer verbatim). The old "input value is a DOM property, not in the hierarchy" claim was FALSE.
- `<select>` node text = ONLY the SELECTED option's text (`selectedOptions.map(o=>o.text).join(', ')`); un-selected `<option>`s are OMITTED from the hierarchy unless the select is `:focus-within`. So the SELECTED value IS matchable and does NOT false-match sibling options (Era "Vintage (1970-79)", League "MLB"; an unset select reads "— Select —"). The old "every option always in the DOM → spurious pass" claim was FALSE for Maestro-web.
- ⚠️ **CORRECTED 2026-07-20 — three feature ROWS were REMOVED from SetAttributesPanel entirely.** `manufacturer`, `cardType`, and set-level `Variation` (parallelName) are gone from `EXPECTED_FEATURES` (see the NOTE in `convex/features/expectedFeatures.ts`: they "only restated breadcrumb info" or were never populated for inserts/parallels). They render NO node, so any `{ id:"Value for Manufacturer"/"Card Type"/"Variation" }` assertion fails. `new-chain-autopopulates-features.yaml` was cut from 7→3 assertions (Era + Card Thickness + Country of Origin) 2026-07-20; the leaf variantType's own-level derivation (cardType/parallelName) is now UI-unobservable — covered in spirit by Era (year-origin) + physical defaults (setName-origin). Text-assertable auto-populated set/VT panel values that DO still render on a fresh custom chain: Era `<select>` "Vintage (1970-79)", Season (=year), Country of Origin "USA", Card Size "Standard", Material "Card Stock", Card Thickness "20pt", Language "English". For a set-vs-card no-cascade proof needing a free-text field at BOTH levels, use **Country of Origin** (`countryOfOrigin`, no hiddenAtLevels) — `signedBy` is `hiddenAtLevels:["set"]` so it renders NO set-panel row (features-propagation.yaml retargeted Signed By→Country of Origin 2026-07-20).
- ⚠️ **CORRECTED 2026-07-20 — Vintage is NO LONGER a text `<span>`.** The shipped NEO-71-74 `SetAttributesPanel` renders ALL boolean/derived features (Vintage, SP, SSP, Reprint, Case Hit, Auto (On Card), Auto (Sticker), Prospect Card, Memorabilia Relic) as a top **toggle-pill row** whose active state is `aria-pressed="true"` (confirmed: `CardFeaturesEditor.test.tsx` "aria-pressed, not a checkbox's .checked (it's not an `<input>` anymore)"; and a screenshot showing a green "Vintage" pill). `getNodeText` does NOT expose `aria-pressed`, so **`{text:"true", id:"Value for Vintage"}` can NEVER match** — the pill's node text is just the label "Vintage". To prove the vintage derivation, assert the sibling **Era `<select>` = "Vintage (1970-79)"** (text-assertable, same year-origin 2-hop copy-down) — a direct Vintage=true value assertion is NOT feasible. `new-chain-autopopulates-features.yaml` Step 6b still carries the stale `text:"true"` Vintage assert (working-tree, uncommitted) and RED because of it — the fix is to DROP 6b (redundant with 6a Era) exactly like the Autographed removal.
- **THE TECHNIQUE:** every control carries `resource-id` = its aria-label ("Value for <Label>" — the DO-NOT-RENAME hook in `SetFeatureRow`; `getNodeText` maps `node.ariaLabel` → resource-id). Assert with a COMBINED selector `{ id: "Value for <Label>", text: <value> }` — matches the single node with BOTH that aria-label AND that value (unambiguous, no breadcrumb/sibling collision). Drive it via `scrollUntilVisible` (each panel row can sit below the 629px fold; maestro-web emits raw bounds so below-fold rows fail a plain `assertVisible` — center outside screen), so the scroll IS the value check (R6-clean). Regex-escape gotcha: "Vintage (1970-79)" has literal parens (regex metachars) → match the inner substring ".*1970-79.*", not the raw string.
- `new-chain-autopopulates-features.yaml` now asserts 6 values at the leaf variantType panel: Era/Vintage/Manufacturer/**Autographed**/CardType/ParallelName. **Reprint was DROPPED** (it became an unreadable checkbox — see [[reference_typed_feature_controls_neo71_74]]; a valueless `<input type=checkbox>` reads value="on" for BOTH states, no `checked` attr in the hierarchy → indistinguishable). **Autographed (select, default "None", originates at setName exactly like isReprint) REPLACES it** and IS readable (select node text = selected option "None"), so it directly re-proves the setName-origin 1-hop copy-down Reprint used to. `sport-level-league-autopopulates.yaml` asserts League="MLB" at the real-Baseball SPORT panel. Each value is uniquely produced by ONE origin level, so asserting values at the leaf proves both copy-down AND own-level derivation.

**Asserting a NEWLY-ADDED node-level default requires FRESH (generation-bumped) node names.** `/testing/reset` (`resetMyTestState`, convex/testing.ts) deletes ONLY the three per-USER tables (publicProfiles/userProfiles/prizePool) — it NEVER wipes the GLOBAL `selectorOptions` catalog. Combined with write-once snapshots, a per-worker custom node created by an EARLIER run predates any newly-added default and renders it blank ("— Select —") FOREVER (no retroactive fill in the E2E path; only `runCardFeaturesBackfill` fills existing rows, and it isn't run there). So when you add an assertion for a just-added setName/variantType-level default, you MUST bump the flow's custom node names so the drill CREATES them fresh with the CURRENT derivation. For autographed (2026-07-15), new-chain bumped SET_NAME/VARIANT_TYPE `WOSet-`/`WOVT-` → `WOSet2-`/`WOVT2-`; bump the trailing digit again (…2→…3) for the next new default. Ancestors (sport/year/mfr) stay reused on purpose — reusing them additionally proves copy-down into a NEW child under a PRE-EXISTING parent (the common real-world "operator adds this year's set under a known maker" case). Symptom when you forget: the 5 pre-existing features assert GREEN, the new one fails `Element not found: text <val>, id Value for <Label>` and the screenshot shows "— Select —".

**Root fully-custom chains at the per-worker CUSTOM sport, not real Baseball.** util-drill-to-custom's "custom YEAR under a REAL sport (Baseball, which has a `Search years` input)" path is FRAGILE: it goes search→not-found→eraseText→`scrollUntilVisible id "Add custom Years"`, which repeatedly threw CDP `Failed to execute JS` and failed (`Element not found: Add custom Years`) even though the "+ Custom" button was on-screen. No existing flow exercises that combo (all Baseball flows use a REAL year like 2024). FIX: pass `SPORT: "E2E Test Sport ${WORKER_INDEX || 0}"` (the suite's standard per-worker custom sport, auto-created by util-drill Level-1 if absent) — under a custom sport every level is short-list custom → the clean Add-custom drill path (same one util-drill-to-custom-set uses). Era/vintage still derive from the custom year (sport-independent). Bonus: fully per-worker subtree (sport root included) = zero cross-worker doc contention.

**League on shared dev — UPDATED 2026-07-12:** the real "Baseball" sport on the shared dev deployment NOW has `features.league="MLB"` (backfill ran or it was re-synced fresh) — `sport-level-league-autopopulates.yaml` asserts League="MLB" at the Baseball SPORT panel and passes locally. So a League-value assertion is currently safe on shared dev AND CI. (Historically it could be empty if the Baseball row predated write-once: copy-down only populates rows created AFTER the change; `runCardFeaturesBackfill` fills existing rows; re-sync does NOT recompute an existing row's snapshot.) If it ever regresses to "— Select —" locally, that is the stale-node data state, not a code regression. Re-sync does NOT recompute an existing row's snapshot (storeSelectorOptions only sets features on FRESH inserts; existing-row test confirms league is preserved, not recomputed). CI is immune: its fresh Convex preview syncs Sports fresh (new storeSelectorOptions) so Baseball gets league:MLB. ⇒ any assertion depending on League populating (League value, or the collapsed "N missing" badge count) is env-dependent — don't assert it. Rooting at a custom sport sidesteps this entirely (league never derives for a custom sport, and we don't assert it).

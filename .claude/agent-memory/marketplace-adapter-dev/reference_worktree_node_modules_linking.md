A fresh worktree has no `apps/web/node_modules`, and `apps/web/link-deps.sh`
refuses with "Primary checkout has no node_modules: <repo root>" because it
tests `$primary/node_modules` where `$primary` is the git worktree root, not
`$primary/apps/web`. Workaround that keeps its drift guard:

```
cd <worktree>/apps/web
cmp package-lock.json <primary>/apps/web/package-lock.json && \
  ln -s <primary>/apps/web/node_modules node_modules
```

Then `npx vitest run ...` and `npm run typecheck` work. `npm run lint` may
still fail to load `eslint.config.mjs` if the primary's install is stale
relative to its lockfile (a plugin missing from node_modules); that is an
install problem in the primary, not a lint finding — and eslint visits no
plain `.ts` file anyway (see [[eslint-does-not-cover-plain-ts]]), so Convex
changes are not gated by it.

**How to apply:** run this before the fast gates in any new worktree; if lint
cannot load its config, report it as "not runnable" rather than churning.
